Title
Churn prediction on KKBOX with point-in-time features and calibrated probabilities

Status
Portfolio project. Read LIMITATIONS.md in the repo before quoting any figure below.

Problem and metric
Predict churn one month ahead. Score on log loss. See CITES.md.

Approach

* Rebuilt labels with the 30-day rule and tests. (Two implementations currently disagree on the
  day-30 boundary; see DECISIONS-PENDING.md.)
* DuckDB features with as-of windows, plus tests that fabricate post-cutoff events and assert
  they are excluded.
* Baselines, XGBoost, LightGBM, isotonic calibration.
* SHAP endpoint with an explicitly flagged approximation fallback. Rules for next best action;
  their effectiveness has not been evaluated.

Results (recorded; measured on the window that was also used for hyperparameter tuning,
so not held-out)

* Log loss. pre = 0.4130, post = 0.1127.
* ROC AUC. 0.9696. No confidence interval is computed anywhere in the repository.
* Brier. pre = 0.1255, post = 0.0331.
* Backtests. Not produced. The backtest driver never calls its evaluation function and the
  committed eval/backtests.csv is empty.
* Drift. scripts/psi_scores.py exists; no PSI result is recorded.

Demo

* React dashboard over checked-in exported JSON and 200 sample members.
* Output. score, rule-selected action, and placeholder explanation factors (the live API
  path does not currently match the FastAPI routes).

Reproducibility

* make app for local startup; Docker and Docker Compose configuration included.
* CI workflows exist but are not gating: lint is non-blocking, only two test files run, and the
  calibration, integration and backtest steps use continue-on-error.
